# Market Research Update: May 2026

This document captures the public internet research used to update Qeetro's strategy on May 15, 2026.

It is not a substitute for paid analyst research, customer discovery, or win-loss analysis. It is a source-backed snapshot of what major competitors and adjacent platforms publicly claim today.

## Executive Finding

AI and agents are no longer a unique claim in work management.

Linear, GitHub, Notion, ClickUp, Asana, GitLab, Plane, and Motion all publicly position around AI workflows, agents, connected context, enterprise search, automated coordination, or AI teammates. The market has moved from "AI summaries" to "AI workers inside the workflow."

The strategic implication is blunt: Qeetro cannot win by saying it has AI or agents. It must win by being the best governed execution substrate for software teams, with a stronger software-specific work graph, better developer surfaces, sharper defaults, and more trustworthy agent governance than broad work platforms or code-hosting platforms.

## Research Method

Sources reviewed were primarily official product, pricing, docs, and marketing pages. That makes this research useful for positioning analysis because it reflects how competitors want buyers to understand them.

Limitations:

- Official pages overstate product maturity.
- Some public pages could not be extracted reliably, especially Monday.com and Height.
- This document should be refreshed with customer interviews and hands-on product testing before major pricing, packaging, or roadmap commitments.

## Source-Backed Market Signals

### Atlassian And Jira

Sources:

- [Atlassian Marketplace](https://marketplace.atlassian.com/)
- [Jira Service Management](https://www.atlassian.com/software/jira/service-management)

Public signals:

- Atlassian Marketplace remains a major ecosystem with project management, software development, admin, data, AI, and Rovo agent app categories.
- Jira Service Management publicly emphasizes AI agents, smart context, AI alert grouping, AI incident summaries, DevOps collaboration, and service management across IT, HR, facilities, engineering support, and employee support.
- Atlassian claims broad enterprise trust and a large customer base in service management.

Strategic reading:

- Atlassian's AI posture is serious, not cosmetic.
- Jira's weakness is not lack of AI. It is the configuration-heavy and broad enterprise-service center of gravity that makes semantic consistency hard.
- Qeetro should position Jira as legacy coordination infrastructure, not as a product with no AI.

### Linear

Sources:

- [Linear homepage](https://linear.app/)
- [Linear features](https://linear.app/features)
- [Linear AI](https://linear.app/ai)

Public signals:

- Linear now positions as "the product development system for teams and agents."
- Its public AI page highlights Triage Intelligence, duplicate detection, semantic search, Pulse updates, agents, Linear MCP, and AI workflows that operate quietly inside product development.
- Linear's homepage shows agents such as Codex, GitHub Copilot, Cursor, and others acting inside Linear workflows.
- Linear has expanded beyond issue tracking into intake, planning, build workflows, diffs, monitoring, insights, dashboards, releases, customer requests, and code intelligence.

Strategic reading:

- Linear is no longer accurately described as only a faster issue tracker.
- It is Qeetro's most important direct strategic threat among modern software-team tools.
- Qeetro must beat Linear through a deeper cross-tool execution graph, more explicit governance, stronger enterprise controls, richer agent auditability, migration discipline, and category authorship around software execution.

### GitHub

Sources:

- [GitHub Issues](https://github.com/features/issues)
- [GitHub Projects docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)
- [GitHub Copilot](https://github.com/features/copilot)

Public signals:

- GitHub Issues and Projects support sub-issues, views, custom fields, project insights, templates, automations, CLI access, mobile access, and tight issue and pull request integration.
- GitHub Projects is explicitly framed as flexible project planning for developers, next to the code.
- GitHub Copilot now emphasizes cloud agents, third-party agents, model choice, CLI workflows, MCP integrations, enterprise controls, audit logs, and governance for agent usage.

Strategic reading:

- GitHub owns developer identity, repository context, PR context, code workflow, and agent-assisted coding.
- Qeetro should integrate deeply with GitHub instead of trying to replace it.
- Qeetro's opportunity is the execution layer above and around code: product intent, docs, roadmap, customer feedback, dependencies, cross-team coordination, and governed execution intelligence.

### Notion

Sources:

- [Notion AI](https://www.notion.com/product/ai)
- [Notion Projects](https://www.notion.com/product/projects)

Public signals:

- Notion now presents AI as a 24/7 AI team with Notion Agent, Custom Agents, AI Meeting Notes, Enterprise Search, custom permissions, model-agnostic workflows, no training on customer data, and enterprise security claims.
- Notion Projects emphasizes configurable databases, timelines, charts, automations, custom properties, forms, permissions, dependencies, automated sprints, GitHub and Jira integrations, and docs alongside project work.

Strategic reading:

- Notion is not only a docs competitor. It is a connected workspace and AI-agent competitor.
- Its strategic center remains flexible knowledge work and documents, which creates an opening for Qeetro to specialize in software execution rather than broad workspace flexibility.
- Qeetro should not copy Notion's flexibility. It should make docs valuable only where they improve execution context.

### ClickUp

Sources:

- [ClickUp AI](https://clickup.com/ai)
- [ClickUp features](https://clickup.com/features)
- [ClickUp for software teams](https://clickup.com/teams/software)

Public signals:

- ClickUp Brain is positioned as a company-wide AI that knows tasks, docs, conversations, decisions, history, connected apps, preferences, and work context.
- ClickUp publicly markets Super Agents, Ambient Intelligence, connected apps via MCP, enterprise search, premium models, AI notetaker, AI fields, AI cards, chat, docs, dashboards, 1000+ integrations, and a software-team lifecycle from roadmap to release.
- ClickUp leans hard into broad consolidation: "The everything app for software teams" and "All the features, one platform."

Strategic reading:

- ClickUp validates demand for connected work AI and consolidation.
- It also demonstrates the strategic trap Qeetro must avoid: breadth, surface sprawl, configuration, and generic-work positioning.
- Qeetro should win by being narrower, faster, more trusted by developers, and more semantically coherent for software execution.

### Asana

Sources:

- [Asana AI](https://asana.com/product/ai)
- [Asana Goals](https://asana.com/product/goals)

Public signals:

- Asana AI emphasizes AI Teammates, AI Studio, smart workflow galleries, smart assists, AI connectors, trust controls, permissions, partner data restrictions, and embedded AI inside workflows.
- Asana Goals connects goals to projects, portfolios, dashboards, status updates, and automatic progress tracking.

Strategic reading:

- Asana is credible in enterprise cross-functional work management and AI workflow automation.
- It is not developer-native and does not own the software delivery signal layer.
- Qeetro should avoid broad Asana-style enterprise work management until software execution is won.

### GitLab

Sources:

- [GitLab Agile Delivery](https://about.gitlab.com/solutions/agile-delivery/)
- [GitLab Duo Agent Platform](https://about.gitlab.com/solutions/ai/)

Public signals:

- GitLab positions agile planning as integrated with the DevSecOps lifecycle, including issues, epics, boards, dependencies, roadmaps, reports, dashboards, design management, wikis, and value streams.
- GitLab Duo Agent Platform emphasizes specialized agents, an AI catalog, custom agents, agentic flows, event-driven execution, policy-driven AI controls, traceability, self-hosted models, and DevSecOps context.

Strategic reading:

- GitLab is the strongest integrated code-to-deploy platform competitor with serious agent-governance language.
- It is most dangerous where customers already standardize on GitLab for the full software lifecycle.
- Qeetro's opening is cross-tool execution outside a single DevSecOps suite, especially where GitHub, Slack, Notion, Figma, customer systems, and multiple engineering teams must be coordinated.

### Plane

Sources:

- [Plane homepage](https://plane.so/)
- [Plane pricing](https://plane.so/pricing)

Public signals:

- Plane positions as project management and knowledge management for teams and agents.
- Plane combines projects, wiki, Plane AI, self-hosting, air-gapped deployment, mobile, apps and agents, MCP, Slack integration, APIs, webhooks, SDKs, Projects-as-Code, migration tooling, and enterprise security.
- Plane's pricing page emphasizes AI credits, wiki, workflows, approvals, dashboards, importers, GitHub and GitLab sync, SSO, LDAP, audit logs, and self-hosted deployment.

Strategic reading:

- Plane is no longer just an open-source Linear alternative. It is a serious developer-forward, self-hosted, AI-aware execution competitor.
- Qeetro should treat Plane as a direct watchlist threat, especially for regulated, sovereign, open-source-friendly, and migration-sensitive buyers.
- Qeetro should not chase full self-hosting too early, but it must design architecture so a future self-hosted or dedicated-cloud path remains possible.

### Motion

Sources:

- [Motion homepage](https://www.usemotion.com/)
- [Motion AI Project Manager](https://www.usemotion.com/project-manager)

Public signals:

- Motion markets AI tasks, AI projects, AI docs, AI notetaker, AI calendar, AI workflows, AI reports, API access, and AI project management.
- Motion emphasizes automatic planning, prioritization, calendar optimization, status movement, capacity planning, predictive project completion, and reduced check-ins.

Strategic reading:

- Motion is not a direct software-execution competitor, but it is strategically useful.
- It proves users understand the value of automatic prioritization, capacity-aware planning, and AI-generated project structure.

## Strategic Implications For Qeetro

### 1. AI-Native Is The Category, Not The Differentiator

Buyers will hear AI-native claims from many vendors. Qeetro must define a stricter standard:

- Software execution graph.
- Source-backed state inference.
- Agent identity and governance.
- Developer-first programmatic surfaces.
- Enterprise controls without admin-heavy UX.
- Measurable coordination-tax reduction.

### 2. Linear And Plane Are More Dangerous Than The Earlier Strategy Assumed

Linear is moving into teams and agents with strong design and developer trust. Plane is moving into AI, self-hosting, MCP, Projects-as-Code, and enterprise deployment. These are not lightweight competitors.

Qeetro must beat them through focus, execution quality, governance depth, and a clearer category frame.

### 3. GitHub And GitLab Own Developer-Agent Gravity

GitHub and GitLab can bring agents directly into code workflows. Qeetro should not fight the code-hosting layer directly. It should integrate with it and own the layer where product intent, roadmap, docs, dependencies, customer input, and delivery reality are reconciled.

### 4. Broad Work Platforms Validate The Problem And Define The Trap

Notion, ClickUp, and Asana prove that customers want AI with context, connected work, and automation. They also show the risk of generic breadth.

Qeetro's advantage must come from being more specific: software teams, developer trust, execution semantics, and AI governance.

### 5. Enterprise AI Governance Must Move Earlier

Competitors now publicly mention data controls, no-training commitments, audit, permissions, model choice, usage analytics, and agent governance. Qeetro cannot postpone these primitives until late enterprise phases.

MVP does not need full enterprise administration, but it does need:

- AI action logs.
- Source citations for important AI outputs.
- Permission-aware retrieval.
- Agent identity placeholders.
- Clear enable, disable, and approval controls.
- Explicit data-use policy.

### 6. Migration And Integration Are Strategic, Not Supporting Work

Multiple competitors now market imports, integrations, MCP, APIs, and connected search. Qeetro must treat migration from Jira, Linear, GitHub Projects, Notion, ClickUp, and Plane as product wedge work.

### 7. The Category Narrative Must Be More Disciplined

The old argument was: incumbents have project management, Qeetro has AI-native execution.

The updated argument is: many platforms now claim AI-native work. Qeetro defines the rigorous software-execution standard those claims must satisfy.
